# RC37 动作、镜头与 F8 调参修正

Minecraft 1.21.1 / NeoForge / Blacklight: Ascension 0.2.0-rc.37。

针对“F8 调参后偶发反向跑”和“普通地图中人物移动、腿不跑或动作卡住”检查了输入、客户端预测、服务端移动、步态时钟、落地过渡、镜头跟随和配置读写。以下是已修改的具体路径；这些问题与用户现象吻合，但没有用自动操作复现用户的全部场景，不能以编译成功代替实际手感验收。

## 动作连续性

- WALK/RUN 两个 Epic Fight 槽共用同一条地面步态时钟。旧代码切回另一个槽时，超过 0.2 秒未采样就重置时钟；复杂地形反复切换、低帧率和短暂不可见时，容易反复从动作开头播放。现在地面循环不按这种短时间间隔重置，跨槽混合也使用同一片段选择结果。
- 动作速度结合本刻实际位移；台阶碰撞已经把速度清零但人实际移动了一段时，腿部速度不会只跟着剩余速度骤降。传送或明显位置修正的位移被排除。
- 步态过滤仍在，但已有移动时不会暂时回退到 IDLE。轻落地且持续移动时保留步态；重落地最低表现时间后可继续跑，避免恢复阶段一直覆盖腿部动作。
- 自由移动的身体朝向优先依据实际行进方向，接近静止时用输入方向起步。冰面惯性尚未掉头时，避免身体先转到反方向而造成倒跑；统一左右方向符号。

## 输入与镜头

- 输入方向以基础镜头朝向为参照；此前一些路径使用已被前置改写的人物朝向，再叠加一次 S/A/D 偏角，可能与镜头和实际移动不一致。
- 移动包新增镜头 yaw，保持按键不变而转动镜头时也同步。客户端预测、服务端疾跑、初始墙面探测和方向攻击使用同一个参照。震屏和长变形镜头角度不参与移动方向。
- 疾跑的水平加速和转向使用两端共用的实现，考虑 W+A/D 的实际方向，并在主动加速时衰减侧向、反向残留。加速度设为零仍保留惯性。极速、升级和装甲速度上限继续生效。
- 跟随镜头经过上一个镜头位置时不再直接翻转 180 度；地面自动旋转有角速度限制。高速移动、低帧率时的连续位移不再仅凭固定八格阈值当作传送而重置镜头。
- F8 高速 FOV 现在也作用于新的第三人称镜头，速度变化做平滑，原版动作缩放与长变形仍参与最终视野。没有叠加两遍移动 FOV。

## F8 审计与修改

- 只在未开放联机的单人世界开放编辑，沿用现有限制。打开后暂停世界，调整完成再继续，避免拖滑条期间惯性和动作继续推进。
- 面板分两页，每页六项，适应 Minecraft 最小 GUI 高度，避免底部参数和保存按钮出屏。
- 增加“保存关闭”“恢复默认”“撤销调整”。撤销恢复到本次打开前的参数；恢复默认不会在后台自动执行。
- 配置访问、批量快照使用同步，客户端和集成服务器不再无同步地读写这些全局值。
- 跳跃最小值与最大值保持有序；两个关联滑条显示实际生效值。非法单个配置项独立回退，不再让后续有效项停止加载。
- 保存先写临时文件再替换，失败时保留界面并提示失败；不再未检查结果就显示保存成功。
- 多人服务器参数只在该连接期间覆盖客户端，退出后还原本地设置，避免回到单人世界时 F8 显示上一台服务器的参数。

没有重置用户当前配置。排查时读到加速度 0.25、极速 2.5，均为面板允许的上限；这些合法设置应由运行逻辑正确处理。

## 交付与验证

本版沿用 RC36 的全部 222 份私有动作/镜头资源，逐份保持一致。本轮修改运行代码与 F8 界面；保留 Epic Fight、GeckoLib 前置和未感染时的 Minecraft 生存行为。网络协议更新为 34，客户端与服务器需同步更新。

执行 Java 编译、assemble、安装包内类文件与资源静态核对、Git 空白检查。不运行自动化游戏操作、GameTest 或自动化验收。用户当前运行的 RC36 进程未被关闭；需要退出并使用 RC37 启动后，才能实际体验这些修改。

本版没有宣称完成原版引擎的一比一移植，RC36 文档列出的剧情镜头和原版算法差异仍适用。
