# RC28：蓄力跳与滑翔输入修复

## 原因与改动

旧实现服务端只判断离地、按住空格、下降和无横向碰撞；跑动蓄力仍能进入滑翔分支。客户端另用离地超过两 tick 和宽松竖直速度区间判断，没有排除跑动蓄力，导致跨小落差也会显示滑翔。

现在客户端和服务端共用 JumpInputState：地面或贴地按下的这一轮空格属于蓄力，爬墙期间按住的输入属于墙面动作。在松开前，即使蓄力因持续离地取消，也不会把同一次按住改解释成滑翔。落地时仍按住的空中输入也不能在下一个台阶重新开启滑翔。

贴地按下空格会保留最多五 tick（0.25 秒）的蓄力请求；只有实际接地才启动蓄力。贴地范围为脚下 1.05 格内有实体支撑，且竖直速度处于 -0.5 至 0.035。请求超时、松键、进入武器动作或墙面动作时清除，不制造接地或自动补一次空中跳跃。

正在蓄力时保留原有五 tick 的短暂离地容错；离地期间不增加蓄力，持续离地后取消。客户端同步取消蓄力姿势，避免仍显示蓄力或松键时播放无效起跳。

真正滑翔需单独的空中按键、连续离地超过五 tick、竖直速度低于 -0.02、无横向碰撞且脚下 1.05 格内没有支撑；蓄力和墙面动作优先。跳跃仍为地面按住空格、松开起跳；起跳后再次按住空格，在足够离地并开始下降时滑翔。退出滑翔时清除尾迹标记。

这些阈值是 Minecraft 地形适配，并非声称逐项复制原版引擎。

## 构建与使用

RC28 保留 RC27 全部 206 个本地私有动作及配套数据。网络字段和协议号 25 不变，客户端和服务端应同时更新，避免新旧判定混用。

只进行 assemble 编译打包与包内完整性核对；未运行自动测试、GameTest 或游戏内自动验收。实际蓄力、连续方块地形及多人输入手感待用户试玩。

当前运行的 RC27 不会热更新；需退出游戏、备份存档、更换 JAR 后重启。含原版派生动作的包仅供本地私人使用，不公开上传。
