# RC33：黑光饥饿修复与目标判定审计

Minecraft 1.21.1 / NeoForge / Blacklight: Ascension 0.2.0-rc.33。网络协议 30，客户端与服务端必须一起更新。

## 黑光模式的饥饿

已感染且处于黑光模式时，隐藏饥饿条，绕过 Minecraft 的起跑及持续冲刺食物门槛；服务端跳过 FoodData.tick，并停止普通运动、跳跃、攻击的食物疲劳积累，因此不触发该循环中的饥饿伤害和食物自然回血。不会每帧把食物强行填满。普通模式使用原有食物数据和规则。和平难度的独立恢复机制、吸收、药水与其他模组回血不是此次修改对象。

## 目标判定审计：确认并修复

| 问题 | 证据与结果 |
| --- | --- |
| 准星关注被当成手动锁定 | 原 CombatTargeting.locked 直接读取 Epic Fight ServerPlayerPatch.getTarget。检查已安装 21.17.3.1 字节码，镜头在未锁定时也通过 CPSetPlayerTarget 同步 focusingEntity。现增加独立 TargetLockPayload，只发送实际锁定状态；服务端不再从该关注字段推断手动锁定。 |
| 锁定够不到时抢邻近目标 | 原攻击、抓取在锁定不满足招式距离后继续扫描候选。现有效手动锁定存在时只尝试该目标；不满足本招条件则落空或提示没有可抓目标，不自动换人。地刺的有效锁定不满足施法条件时不改投前方。 |
| 扑击追踪缺视线判断 | 原空中扑击直接读 EF target，只检查存活、同维度、友军及距离。现使用独立锁定、统一有效性、实体碰撞箱距离和实际方块视线。 |
| 过滤条件分散且不一致 | 武器、旧利爪攻击、地刺、疾跑撞击、扑击接触改用共同的伤害候选过滤：存活、未移除、同维度、非旁观、非无敌、非友军、非吸收中；玩家还需队伍伤害许可及服务端 PvP 开关。主动选敌另排除隐形目标；范围攻击仍可以实际接触隐形敌人。 |
| 有限命中数挤掉锁定对象 | 旧利爪和疾跑撞击按最近目标或实体遍历顺序限额。现对已经进入接触候选集合的有效锁定目标优先，再按距离、实体 ID 排序。不会扩大攻击范围。 |
| 连招缓存使用上一招范围 | 原缓存输入通过 active.move 选目标，现使用实际 followUp 招式范围。 |
| 持续追踪漏掉新状态 | 武器追踪复用统一 selectable，补入移除、隐形、无敌和 PvP 状态检查；失去合法目标时停止追踪。手动选敌同步在镜头变化及攻击输入前执行。 |

## 已核查但不能误称为根因的部分

没有发现按当前生命值或最大生命值降序选敌的实现。自有自动攻击选择按前方距离、朝向、实体 ID；已安装 Epic Fight 的切换候选按屏幕横向位置排序，不按生命值。生命值在吸收系统中用于“大型目标必须削弱”的门槛以及恢复量，不是攻击选敌权重。此次修复确认存在的锁定混用和回退路径；尚未在用户原现场复现“最高生命值必然抢锁”的因果关系。

镜头已锁定有效对象时，普通关注变化不能替换它；主动切换目标、自由切换输入、死亡后 Epic Fight 配置允许的接续锁定仍保留。取消锁定或死亡、移除、切换维度、切回普通模式后，旧锁定不会继续驱动本 Mod 战斗。普通模式的 Epic Fight 行为不受黑光镜头限制。

## 范围与剩余边界

锁定优先是攻击朝向、选敌和命中限额优先，不代表范围伤害只打一个人。拳套溅射、地刺、横扫及身体接触依然可以伤及接触范围内的其他敌人。已出手的攻击保留本次选定目标，新的手动切换在下一次选择时生效，避免攻击中段瞬间转移命中体积。

视线仍使用目标碰撞箱中心射线；中心被挡而边缘露出的目标可能暂时不被自动选择。第三方模组自定义伤害事件、特殊多部件 Boss 的各部位判定及镜头左右切换评分没有在本轮全面重写。实际密集敌群、边角遮挡和联机延迟场景需玩家试玩确认。

## 验证与安装

已核对本机 Minecraft 1.21.1 / NeoForge 来源中的起跑判断、FoodData.tick、Player.causeFoodExhaustion 与 HUD 层接口，以及已安装 Epic Fight 的镜头方法、目标同步调用和字段。执行编译、打包、Mixin 注册/目标签名静态检查和包内资源一致性检查；不执行自动测试、GameTest 或自动游戏验收。

安装包 `Blacklight-Ascension-MC1.21.1-NeoForge-0.2.0-rc.33.zip`，退出游戏备份后替换旧 JAR。私有动作仍 213 份，与 RC32 全部逐文件一致；没有公开上传。
