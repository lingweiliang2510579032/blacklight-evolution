# RC5：普通生物接收动作与双方位移

针对 RC4 用户反馈：普通生物仍像固定在手上的道具，大型生物也缺少对应反应。

本轮代码检查确认：四足生物被排除在原版接收姿势之外，只走简化反应；导出时剥离的主角 Motion_Root 位移没有交由服务端执行；自定义 Gecko 骨架直接使用 Epic Fight 局部旋转，未转换父骨骼关系。

- 猪、牛、羊、山羊、北极熊和熊猫增加四足接收姿势。按 `QuadrupedModel` 实际顺序映射身体、后腿、前腿，保留原模型初始姿势与比例。
- 吸收动作的主角根位移由服务端执行并同步本机玩家，碰撞仍由 Minecraft 处理。大型攀附使用受限的侧移与重心变化，避免穿进大型身体。
- 同步吸收开始时的场景原点，双方位置根据同一场景计算。抓持阶段可约束接触，释放后目标独立走其位移轨迹，不随主角当前位置或收手漂移。
- 明确禁止旧持有姿势 IK 在吸收阶段回退接管。
- 大型普通模型按对应武器接收姿势变化上身；Gecko 怪物使用身体整体旋转和自身初始父子骨架转换，不再把 Epic Fight 局部旋转直接写入。
- 日志记录吸收开始、释放和结束，包括形态、目标种类、动作、时长及释放时双方位移。用于用户试玩反馈后的诊断，不自动操作游戏。

网络协议 24；本地 `consume-placement.data` 为 schema 4，包含双方根位移及完整身体投影。需与 RC5 同时更新，旧配置不静默退回跟手。

这些仍是 Minecraft 骨架、碰撞和大型攀附适配。原作事件时间表未完整恢复；体型差异、碰撞导致的动作截断和第三方骨架仍需用户验收。只编译打包，不运行自动测试或游戏内验收。
