# P1 本地原始资源核查（R22）

2026-09-20：用户提供本机原版游戏作为研究来源。原文件只读，解压数据、完整关节曲线、源骨架和诊断视频保存在仓库外的私有研究目录，不是本 Mod 的可发布资产。

## 实际读到的内容

RZ 包由 16 字节头和 zlib 数据组成；解压长度与头声明一致。P3D 树中能读取 Skeleton_2、Animation、AnimationGroup 和内联/外置压缩曲线。以下数量仅为 `PTRN` 骨骼动画，不含相机等其他 Animation 类型。

| 包 | PTRN 数 | 已确认的代表内容 |
| --- | ---: | --- |
| alex | 533 | 基础移动、抓取、空中锤肘等 |
| alex_blades | 14 | attack_A/B/C/D、dash、air_attack |
| alex_claws | 9 | 4hitcombo、groundspike |
| alex_hammerfist | 14 | 3hit_combo、4hit_combo、两段转接、air_toss |
| alex_whipfist | 16 | 3hitcombo、longshot、sweep、pullback、抓取 |
| alex_musclemass | 5 | 肌肉形态抓取及变身相关 |

普通主角与多数武器骨架为 67 关节，鞭拳骨架为 90 关节。18 个重点片段已提取旋转、平移及缩放诊断数据，源四元数有限值和单位长度检查通过。完整状态机、不同分支的混合、命中体和物理仍不在此次解码证明范围内。

## 时序不能从资源长度直接推断

FIG 所有者树实际对同一资源做裁切和重定时。以下为直接读取的局部轨道，不是根据文档顺序猜出的执行图：

- 刀 A 的 release 使用源帧 5–20，在该节点的 0–0.5 秒播放；收回使用 20–50 帧，在 0–0.666667 秒播放。
- 刀 B 的同一 release 节点含两条连续轨道：10–14 帧对应 0–0.166667 秒，14–33 帧对应 0.166667–0.566667 秒。
- 刀 dash 的冲刺分支 release 使用 11–40 帧，存在相对节点时间 0、0.216667、0.45 秒的三个不同 hit 事件；地面分支另有独立时序。
- 同一时刻可能存在多个不同条件的 hit 记录，不能直接换算成多次伤害。
- 地刺包含蓄势、保持、释放及多个条件分支。负结束时间是源格式标记，不可擅自替换为整个资源长度。
- 鞭拳部分扫击节点的伤害还可能来自子对象或回调；没有直接 hit 记录不等于没有伤害。

## 还原接入要求

先验证源骨架的左右、朝向和关节层级，再重定向到 Epic Fight。关节数不同，需要明确映射躯干、前臂、腕及辅助骨。根位移与足部曲线必须一起处理，不能另配一条无关的推进曲线。

源动画能够解码，不代表目前 Mod 的攻击已经还原。R21 的动画包适配仍是现行行为。R22 当前通过验证的生产变更是普通武器连击在收势中衔接，避免中间强制回待机；97 项单元测试、37 项 GameTest 通过。试作地刺出现头部相交，已恢复之前的生产动画。

本地刀 A 空间映射样板已核对源第 10、20 帧。Epic Fight 的 Hand 实际承载前臂，因此对应源 Elbow；源 Wrist 仅映射至 Tool 作诊断，不能把腕部全局旋转直接用于 Hand。现有武器网格仍绑定 Hand，独立转腕尚未作用于武器。样板保留同源根位移和足端轨迹，但未做 FIG 切段与武器避头，静帧仍有刀臂穿体，因此只保留为私有研究输出，没有接入生产。

## 工具依据

- [Prototype P3D Archive Toolkit](https://github.com/204343414/prototype-Game-p3d)，核查版本 `7115f8e0ba6ecb531100e44e652e71ee697c5adf`。当前 `entity_decoder.py` 支持混合通道；旧单独外部 blob decoder 不足以读取这些武器。
- [EditP3D](https://github.com/Elan-S/EditP3D)，独立核对压缩四元数、half 平移、帧表布局和绝对局部变换约定。

这些项目是格式解释的参考；实际动画数据来自用户本机。没有运行第三方可执行文件，没有将原版曲线复制到公开仓库。

仓库提供 `tools/inspect_prototype_animations.py`，用 Python 标准库只读检查本机安装：

```text
python tools/inspect_prototype_animations.py <原版游戏目录> --out <游戏目录之外的报告.json>
```

它只写文件名、片段名、帧数和骨骼数量等元数据，不导出网格、纹理、骨骼矩阵或动画曲线。实际六包检查结果与上表一致。
