## 证据边界

以下已检索到招式说明，属于二手资料；尚未逐帧观察并核对完整原版动作。浏览器读取演示连续超时，因此没有可验证的动作时间码、关键帧或精确时长。不要根据文字描述凭空填写这些数据，也不要宣称完成原版动作研究。

默认研究对象为 2009 年《Prototype》Alex Mercer。资料中的 Prototype 2 分节必须分开，不能把二代 Blade Tornado、锤拳地刺等直接当作一代招式。

## 返工验收

先取得可观察的原版演示，再对每招记录起手、重心转移、接触姿态、攻击轨迹和收势；关键帧要保留来源和时间码。先做代表招式并与原版并排检查，再扩展完整连段。

客户端实拍必须检查侧面和正面，不能仅看动画 JSON 或骨骼数。伤害生效时间应对应实际刃部或拳肘接触阶段，空中攻击以接触或落地事件衔接。穿头检查仅验证几何安全，不证明动作好看或忠实。

怪物当前共用类人方块构造、缺少足够关节与差异轮廓，属于被否定的草稿。需另行研究原版怪物概念图与实机姿态，不把自创 Stalker/Spitter/Brute 直接称为原版还原。

## R20 边查边做进度

实际观察了锤拳变身短片的 0–6.4 秒连续帧：https://tenor.com/view/prototype-hammerfist-gif-9272304721253253989 。它展示变身，不是攻击：前段身体收紧、手臂变化，后段俯身、双拳沉下，再抬起身体。不能拿它证明已观察肘击或 Hammertoss。

实际观察了本机既有 `original-claws-hd.mp4` 的连续帧：约 0–4 秒为地刺蓄势、手部入地、地刺冒出和收势，后段还有近身斩击。片段有剪辑，不能据此推定所有招式的完整连段长度。

本轮代码迭代（仍需原版逐招动画对照）：

- 刀臂两种特殊攻击先实现三段挥斩，每段独立命中窗口、音效和前进。三段与 44/40 tick 时长是当前适配值，不声称是原版的固定连击数和时长。
- 普通刀臂斩击增加身体转向、挥过后的余势、支撑脚变化。避免让巨大的双端刃直接横穿头部。
- 锤拳空中招式采用折臂、收腿、下压和落地压低的不同姿态；仍以实际落地触发伤害。
- 鞭拳清扫覆盖一整圈，身体转动；鞭中段滞后于末端，末端方向与服务端扫掠判定共用计算。
- 修复连斩中一帧被原版受伤无敌时间拒绝后，整个后续挥击都无法再命中的问题；没有清除或绕过受伤无敌时间。

已有本轮服务器测试覆盖三次独立命中、恢复期间不伤害和背后目标被鞭圈命中。视觉效果必须再检查实际游戏连续画面，不能由测试推断合格。其他武器动作、怪物模型、蜂巢外观仍待返工。

## R22：基础修复、失败试作与参考资源核对

本轮基础连招修改消除了武器两段普通攻击之间的强制待机：输入可在攻击阶段缓冲，完整接触窗口及短暂跟进结束后才进入下一击。队列只消费一次，取消、换形态和超时会重置；连续接触还保留原版 Minecraft 受伤抗性所需间隔。这些是连招运行机制修复，**不是《Prototype》动作还原完成**，没有凭空增加原版连击段数。

新的利爪地刺试作未通过几何审查。实际加载动画在约 **0.5667 秒**的右手/爪顶点到头部包围盒最小距离为 **0**；右手 3106 个唯一顶点的审计有 154 个采样时刻出现顶点接触或进入头部包围盒。左手最小距离约为 0.195 模型单位。该结果不能证明整个三角网格的碰撞情况，但足以否决这次试作。生产地刺 JSON 已恢复到试作前版本，并已按文件字节核对；失败试作仅保留为本地草稿，不进入发布。

新增独立 QA 使用真实服务端地刺请求与三段普通爪击队列，记录侧面和前方三分之四画面、动作状态以及位置。此次截图目标为 316 帧，实际保存 282 帧，记录了 34 个漏渲染帧。因此它验证了动作调用路径，并帮助定位试作问题，**不能标为完整 20 fps 的逐帧视觉验收**。`capture-complete.txt` 只表示捕捉流程完成；应同时读取清单中的漏帧和几何审计结果。
