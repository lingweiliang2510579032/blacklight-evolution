# RC23：方向键转身与吸收收尾

## 攻击方向

此前无目标出招只读镜头朝向，并限制在起手方向左右 90 度；选敌也始终按镜头前方筛选，导致 S/A/D 不能正常改变出招方向。

- 物理方向键先于同帧攻击按键送到服务端；按 S 起手和接下一段时可以朝身后出招，A/D 对应侧面。
- 准备阶段读取镜头相对移动方向，以该方向选择自动辅助目标；旧目标不再无条件保留。玩家明确锁定的目标仍优先。
- 身体朝向、武器视觉、命中范围和位移方向使用同一个攻击方向，镜头不再被服务端追踪目标强制旋转。
- 去掉以起手角度为中心的 90 度硬限制；转速按已解出的 TurningVelocity 换算，有限的 release TimeBegin/TimeEnd 约束追踪窗口。

原版依据来自本地已解码 AutoTargetTrack：普通拳、利爪、刀锋、重锤和鞭拳的准备阶段 UseInput=1，出招阶段多为 UseInput=0；Arc 还有独立的 CheckArc 条件，不能当作身体永远不得转过 90 度的依据。例如普通拳/刀锋准备转速 1800 度/秒，普通拳出招 1200、重锤出招 900。仅使用现有解码数字，未把原版原始资产加入 Git。

边界：这是接入已确认字段，不是完整原版 auto-target driver。没有方向输入时的镜头回退、最近目标排序、蓄力保持期复用准备阶段规则仍属于模组适配。出招后不是每个阶段都能用 S 任意扭转已打出的攻击；方向改变可以在允许的准备阶段或下一段连招生效。

## 吸收不中断与带动画移动

此前玩家/受害者受到任何伤害都会调用 cancel，且吸收奖励、目标移除和动画结束使用同一个时点，导致整段动画全程锁住移动。

- 确认吸收后，玩家受到普通伤害不再取消吸收；压制该阶段 Epic Fight 的受击硬直和普通击退。玩家仍会扣血，死亡仍进行清理。
- 正在吸收的目标暂时不接受外来伤害，避免旁人将其杀死使已确认的吸收失败；只作用于已确认吸收阶段，不给抓取/搬运目标永久无敌。
- 已确认的吸收不再因配对位移改变视线或普通距离检查被取消；抓取/确认时仍检查视线、距离和可吸收条件。
- 目标消失并结算后解开输入、移动锁定；剩余动画以玩家自己的同步快照继续播放，目标移除后也能保留。
- 行走/跑动时下半身使用移动动画，上身继续吸收收尾并在最后 3 tick 淡出；新攻击/再次抓取会接管姿势。大型目标保留必要的根位移适配。
- 登出、换维度、死亡、目标被外部移除等生命周期清理仍保留；抓取尚未确认时的取消规则不属于吸收阶段。

吸收完成时点目前使用 Minecraft 编排值 max(88%, 接触点+12%)，向上量化到服务端 tick，并同步调整回流特效，在原动作尾端保留可移动的收尾。该时点、上身混合与短暂停顿不是已恢复的原版完成事件，不能声称逐帧一致。

## 验证与安装

只执行 assemble 编译打包、静态代码检查和包内容核对，未运行自动测试、GameTest 或自动游戏验收。当前运行中的游戏没有热替换 Java 类，需重启新版才会生效。

保留 RC22 的 202 份本地动作及配套数据、16 项接招元数据，以及研究站、上浮、形态切换修复。客户端和服务端都应更新，不能同时装两个版本。

建议人工试玩：面向前方时 S+攻击；攻击中 S+下一击；A/D 左右切换；明确锁敌时的优先级；普通目标和大型目标吸收中受伤；目标消失后立即冲刺；尾段接新攻击；吸收中死亡/离开世界后是否正常清理。编译通过不代表这些画面和手感已经验收。
