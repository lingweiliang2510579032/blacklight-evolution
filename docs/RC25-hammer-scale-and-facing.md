# RC25：重砸拳套膨胀与后退转身

本次修复两个表现问题：地面拳套重砸始终保持固定大小；未主动锁敌时，向后移动仍可能面朝镜头前方。

## 重砸缩放

原版 `prototype_hammerfist/surface/ground/attacks/drop_swing` 使用 `alex_hammer_devastator`。P3D 的 `Forarm_R/SCL` 和 `Wrist_R/SCL` 都含有动态缩放，三个轴在该招中相等。源第 0–10 帧膨胀，通道峰值分别为 1.92578125 和 2.435546875，第 121 帧仍保持峰值，第 147 帧回到 1。FIG 将这些源帧分配给起手、蓄力、释放和收招，不能将整段 P3D 的帧号直接当作游戏内招式经过时间。

既有 retarget 虽读取 SCL，但在 `Retarget.frame` 中用旋转、固定骨长重建目标关节矩阵，丢失了这部分形变。RC25 通过 `tools/export_hammer_scales.py` 按现有 `hammer_contract.py` 的相同时间段导出独立曲线，覆盖 `hammer_quake`、`hammer_quake_charge`、`hammer_quake_charged`。蓄力释放的首段混合也与已有身体动作保持一致。当前没有给未核实的空中肘砸添加膨胀，也没有把地面重砸的曲线强行套给全部拳套招式。

运行时优先读取实际 Epic Fight 动画播放器的插值时间；蓄力停帧时拳套保持相应大小。动作结束、被打断或接入未配置的其他动作后，短暂混合回原尺寸。切换武器或死亡会清除缓存。

自制模型将前臂、拳头合并在一个网格中，因此在肘部固定接缝、前臂和腕部之间连续映射两条缩放曲线，并修正形变后的法线。该空间映射属于 Minecraft 模型适配；不能将 2.44 直接称为原版最终世界空间的拳头倍率。本次不改伤害、范围、击中窗口或位移数据。

曲线仅写入私有 `hammer-scales.data`，不进 Git；含原版派生动作的本地构建仅供用户私人使用。Gradle 的本地动作打包清单要求此文件，防止漏包。

## 自由移动朝向

旧判断使用 `patch.getTarget()!=null` 排除自由转身，但当前 Epic Fight 的 `LocalPlayerPatch.getTarget()` 返回镜头的 `getFocusingEntity()`，并不代表用户开启了目标锁定。RC25 对本机玩家单独核对 `isLockingOnTarget()`，且忽略已经死亡或移除的目标。

本机角色按当前 S/A/D/W 的镜头相对输入转向，不再等旧移动惯性反转后才转身；仍保持每 tick 最大 24° 的平滑转动，不修改镜头角度。远端玩家在缺少本地移动速度时使用位置差确定朝向。

自由转身期间不再叠加自带 180° 根骨旋转的 `basic_turn` 动画，避免模型外层转一次、骨架又转一次。主动锁敌、攻击、抓取吸收、跳跃蓄力、攀墙和飞行等状态仍由各自逻辑控制朝向。

## 交付与验证范围

运行 `assemble` 编译打包，并核对包内编译类及资源散列。保留 RC24 的 203 个动作/数据文件，新增一个包含三条动作缩放曲线的数据文件，共 204 个。未运行自动测试、GameTest 或自动游戏操作；实际转身和膨胀效果尚待用户在游戏中查看。

没有停止或替换当前游戏实例。退出游戏、备份存档、移走旧版 Blacklight JAR，安装 RC25 后重新启动；多人客户端和服务端需同时更新。依赖版本沿用 RC24。
