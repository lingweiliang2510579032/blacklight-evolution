# RC21：把已核对的原版接招时刻接入运行时

目标是按原版操作与动作节奏逐项还原，不能把使用原版骨骼片段等同于完整复刻。当前仍不是与原版完全一致的版本。

## 此次实际改动

核对已有 FIG owner 数据及 R26 导出器后确认：本地动画包已经按多个原版阶段做过剪裁和变速；不足主要在运行时仍用统一公式计算接招时刻。先前关于“直接匀速播放会不流畅”的说明是机制解释，并不代表当前所有片段都在匀速播放。

新增只读取本地解包 JSON 的提取工具，将 7 个明确的、只监听 Input 且 hook 非负的事件及对应 windup 时钟写入小型元数据表。运行时按这张表衔接已有连招，不再让这些动作套用通用等待公式。表中保留 block、owner 与事件偏移，能够追溯；不包含原版动画、网格或完整脚本。

| 动作 | RC20 接招 tick | RC21 接招 tick | 减少等待 |
| --- | ---: | ---: | ---: |
| 空手交叉拳（muscle_cross） | 11 | 7 | 200 ms |
| 接踢第一段（combo_kick1） | 12 | 9 | 150 ms |
| 膝击（combo_knee） | 15 | 11 | 200 ms |
| 旋踢（combo_spin） | 12 | 11 | 50 ms |
| 双手下砸接段（combo_axe_handle） | 15 | 15 | 0 ms |
| 利爪第一段（claw_auto1） | 10 | 6 | 200 ms |
| 利爪第二段（claw_auto2） | 13 | 7 | 300 ms |

以上是当前本地动作配置下的服务端时间线数值，不是游戏录像测量结果。计算使用导出后的 windup 时间 + 原版 Input hook + 当前动画 link 过渡时间，向上量化到 Minecraft 的 20 Hz。必须保留完整命中窗口：如果原版 hook 早于当前命中结束，则延后到命中结束。无本地动作、时钟不匹配、未核对的招式或蓄力变体仍保留原有规则，不猜测缺失数据。

## 与原版仍有差异的部分

- 输入事件的完整优先级、条件引用及负时间哨兵尚未全部解析。本次只接入明确的时刻，不宣称运行了原版状态机。
- 原版 common/exit_early/jump 与 exit_active/no_dodge/jump 中明确为 Jump Released。RC20 的按下跳跃取消是适配规则；恢复原版的松键退出还需同时核对蓄力值、阶段和目的分支，不能孤立替换一个布尔值。
- 原版 common/stages 的 windup、hold、release 存在 transformationDisallowed。RC20 允许选择无能力立即收起武器是解决轮盘静默拒绝的适配，不是该原版规则的精确复刻。更完整的还原需要带反馈的切换请求与阶段许可。
- 原版 orient/locoSteer 的具体回调、转速和相机控制尚未全部还原；RC20 的转速仍是适配值。
- 受击打断、足部固定、根位移受阻、骨架比例、场景碰撞、镜头和伤害节奏仍需分别处理。Minecraft 20 Hz 服务端与原游戏不同，因此不能承诺逐帧、逐像素一致。

验证范围：干净编译打包、核对元数据与本地动作时钟、核对包内容；遵守项目约定，不运行自动测试、GameTest 或自动游戏验收。实际连击手感和原版逐招对照仍待试玩。

建议试玩：空手左右键交替接拳踢、右键膝击后接下一招、利爪连续单击三段、提前输入下一招与不输入自然收招。保留 RC20 形态清理与 RC19 水中上浮修复。
