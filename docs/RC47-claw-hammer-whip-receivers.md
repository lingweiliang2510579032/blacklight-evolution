# RC47 利爪、拳套、鞭拳受害者表现

本版修正当前三个吸收片段的受害者动作窗口、形变、吸收效果及服务端结算时序。保留 RC46 的刀锋躯干分体和物种骨架绑定。

| 武器 | 本版选定片段 | 改动 |
| --- | --- | --- |
| 利爪 | `alex_claw_grap_crush_head` | 双方按 FIG 的 45–135 帧截取为三秒，接触点和根位移同步裁切；以 1.266667 秒震屏提示作为压头反馈时刻，2 秒开始吸收，头部先压缩和回收，身体随后回收。 |
| 拳套 | `alex_hammer_grap_headdrop` | 接收者按 0–55 帧播放后停留，保留主角后续动作；1.2 秒震屏提示处给砸落反馈和头部压缩，2.4 秒开始吸收。结束时间延后到效果完成，修正约 2.3 秒提前移除目标的问题。 |
| 鞭拳 | `alex_whipfist_grap_lash` | 对齐 0.833333 / 1.133333 秒两个 hit 时刻，1.4 秒开始吸收；生物保留连贯躯体，沿回收方向收缩，移除各肢体独立旋转/卷碎的通用形变。 |

源数据来自本地 `prototype_consume` FIG 节点。这三个选定 receiver 节点没有 spawnGib 记录，因此没有给它们套刀锋切半。利爪压头和拳套砸头的反馈取源 cameraShakeRequest 提示，并非把它们误称为已解出的伤害事件。网格压缩、回收轨迹和效果收尾长度是 Minecraft 适配。

骨架与效果各自使用同一场景的秒时钟：延长拳套的吸收尾段不会把整段动作放慢。服务端在效果尾段结束后发放原有奖励并移除目标；没有改动抓取门槛、治疗量或进化点。原版源提示仍有未知参数，不能声称逐帧完整复刻。

## 尚未覆盖

原版还有利爪 footsweep、拳套 headsmush、鞭拳 come_here 等替代片段。footsweep 和 come_here 的 receiver 节点确有碎块生成记录；本版仍使用上表三段，未增加变体轮换，也未把这些未选择分支的分体效果混入当前动作。大型攀附、猎手专用吸收仍走各自分支。

## 构建与验证

本地包使用独立的 `rc47-motions`，共 224 文件。相对 RC46，保留 219 份文件原样；修改利爪双方、拳套受害者和配套接触/位移资料共四份文件，新增一份 receiver 事件资料。旧 profile 保留。

仅编译、打包并核对包内容；没有运行自动测试、GameTest 或游戏内验收。试玩需重点查看三种武器吸收不同体型时：头和肢体是否随动作变化、拳套效果是否完整出现、鞭打后身体是否保持连接，以及奖励是否只结算一次。
