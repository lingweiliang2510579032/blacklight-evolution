# Blacklight Evolution 项目规划

本规划以“先做可靠核心引擎，再扩展内容”为原则。每个阶段都必须通过画面验收，不能用占位动画进入下一阶段。

## P0：移动与动画底座（当前最高优先级）

目标：先让角色在无战斗时移动正确、流畅、有重量感。

### P0.1 奔跑循环重做

- 为 Epic Fight BIPED 骨架制作原创 `prototype_run` 动画。
- 左右大腿相差半个周期，左右膝盖与脚掌对应屈伸。
- 加入骨盆上下起伏、躯干前倾、肩部反向摆动和落脚缓冲。
- Root 只保留姿态变化，不承担世界位移。
- 按实际水平速度缩放播放速度，避免脚滑。
- 验收：正面能看出左右腿交替；背面无双腿同步平移；侧面落脚点不明显滑动；起跑和停跑有过渡。

### P0.2 蓄力跳跃动画

- `charge_start`：快速降低重心，手臂和利爪后收。
- `charge_hold`：按住空格时动作只播放一次；到达最佳末帧后必须定格，不能从头重复，仅持续增强腿部黑光触手缠绕。
- `charge_release`：腿部爆发伸展、躯干向上、利爪甩开。
- `jump_rise / apex / fall`：上升、顶点、下落三个姿态自然衔接。
- 验收：短按和长按都能看到区别；满蓄力保持最终帧且只追加腿部触手，不重复蓄力动画；动作不会在 `KNEEL/default` 间闪烁。

### P0.3 落地与地板物理反馈

- 按垂直速度分轻落地、重落地和破坏性落地。
- 轻落地：膝盖吸收冲击，快速恢复。
- 重落地：深蹲、相机震动、环形尘土和冲击音。
- 破坏性落地：服务器判定可破坏方块范围，生成裂纹/碎块表现，但遵守破坏规则与性能预算。
- 验收：视觉强度随落地速度变化；动画与接触地面帧对齐；多人服务器结果一致。

### P0.4 残影与同步

- 保留原版疾跑泥土颗粒拦截。
- 检查客户端预测与服务器加速度一致性。
- 将真正的高速残影做成可控效果，只在达到速度阈值时开启，不能把位置回弹或粒子误当残影。
- 验收：普通走路无泥土拖尾、无重复模型、无周期性回弹。

## P1：利爪完整纵向切片

- 重做低重心待机、行走、奔跑、三段爪击、空中攻击和冲刺斩。
- 建立逐帧碰撞盒调试器：左右手、每段攻击、起止时间、偏移和尺寸可视化。
- 完成地刺的插地动作、地面追踪、骨刺爆发、命中反馈和冷却。
- 完成变形 `start / vein_spread / mesh_replace / settle` 四段，暗红血管覆盖原手臂后再出现利爪。
- 验收：手臂不暴露、利爪不离肩、攻击不退回拳击、伤害/距离与视觉匹配。

## P2：移动能力完整化

- 墙壁探测、垂直墙跑、横向墙跑、墙跳和墙壁攀爬。
- 滑翔的进入、保持、转向、退出与落地衔接。
- 空中冲刺次数、方向、速度曲线、残影和冷却。
- 移动能力加入 EP 解锁和升级参数。

## P3：吞噬、伪装与成长

- 抓取、正面吞噬、潜行吞噬、恢复生命和生物质。
- 保存被吞噬者外貌，完成伪装切换和警戒逻辑。
- 记忆网数据结构、记忆片段 UI 与剧情触发接口。
- EP 获取、能力树、升级菜单与存档迁移。

## P4：其他能力形态

按独立模型、独立动作、独立碰撞与独立调参依次制作：

1. 巨锤
2. 鞭拳
3. 肌肉增强
4. 刀刃
5. 护盾
6. 铠甲
7. 热视觉
8. 感染视觉

不得通过简单缩放利爪模型冒充其他形态。

## P5：世界内容

- Hunter 作为首个完整敌人纵向切片，并用于解锁利爪。
- 军方、Blackwatch、感染者三势力和警戒系统。
- Leader Hunter、Super Soldier、Hydra、Elizabeth Greene、Supreme Hunter。
- APC、坦克与直升机。
- 主线任务、支线事件、感染区与军事基地。

## P6：UI、性能和发布

- 能力拨盘、生命/生物质/EP HUD、升级菜单、记忆网。
- 客户端特效分级与低配置模式。
- 专用服务器、多人同步、死亡/维度切换/重连回归。
- 配置迁移、崩溃报告、安装说明和正式版本打包。

## 阶段门槛

每个 P0/P1 子项都采用相同门槛：实现 → 自动测试 → 开发客户端测试 → 用户画面验收 → 固化预设 → 进入下一项。当前下一项固定为 **P0.1 奔跑循环重做**，随后是 **P0.2 蓄力跳跃动画** 和 **P0.3 落地物理动画**。
